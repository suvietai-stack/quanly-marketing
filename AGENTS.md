# Architecture rules
- Password management: src/lib/password.ts shares validation and fake-email guards; changeOwnPassword verifies via a temporary non-persisting client before updateUser; adminResetPassword enforces hierarchy, hourly cap and account_security_logs; sync_profile_email keeps confirmed Auth/profile emails aligned — preserves sessions and one security policy.
- PasswordInput keeps independent visibility/caret; toggles never submit or invoke auth/storage — preserves security.
- Signal list surfaces delegate to the existing detail Sheet through shared selection-aware interaction guards; keyboard activation lives on the customer-name control, not table rows; custom child actions opt out with data-signal-interactive — preserves table semantics, copy and independent actions without duplicate opens.
- ChipiAssistant mounts once per user in AppShell and observes NotificationBell's recipient-scoped cache; preferences and greetings/dedupe are user-keyed; decoration never overrides business states — no second delivery channel.
- Zalo rotating tokens use separate non-reclaimable leases and version-fenced atomic pair commits; hourly care schedule runs maintenance, UI derives watchdog health, notification claims exclude active owners and fence completion — avoids single-use refresh and duplicate-send races.
- Zalo CS uses plain text via zaloSend.ts; only explicit token rejection allows one rotation/re-send, only explicit quota rejection is auto-retryable, ambiguous and format failures stop; OAuth and send diagnostics are independent and old failed notifications stay held — prevents unsupported templates, paid fallback and duplicate replay.
- Signal KPI: acceptTime.ts unchanged; atomic progression_save; scoped RPCs derive VN periods from Sale segments. Tracking always on; periods due before rule-start are retrospective, not KR. Reminders keep Zalo/Push off.
- Personal OA reminders mount once in AppShell, use authenticated user-scoped link reads and safe OA health fields, and store per-user browser snoozes; only existing verified webhook updates establish interaction — navigation and opening OA never renew eligibility or affect GMF.
- Tiền Về resets use Super-Admin-only fin_reset_* RPCs with explicit confirmation, table lock before shared advisory lock, private scoped JSON recovery snapshots and atomic dependent deletion; fin_operation_guard ignores bank INSERTs at/before reset_at — prevents replay and concurrent reset inconsistencies.
- Leave writes only via SECURITY DEFINER RPCs checking `private.sig_can` and server time; client tables SELECT-only — prevents bypassing permission/deadlines.
- Change `src/lib/leave/calc.ts` and `private.leave_eval` together — keeps preview and authoritative calculation aligned.
- Read app_branding for UI/server share metadata — crawlers cannot run client updates.
- Attendance (att_* RPCs) is separate from leave; UI split /leave vs /attendance sharing backend; /leave?att= redirects. Gear settings on both pages reuse the shared Role store (updateRole) and LeaveSettings (mode leave/att); att.settings may save only the attendance key (enforced in leave_settings_save).
- Sao uses allowlisted programs, activation windows, per-program ledger uniqueness and event fences; KPI counts verified Tasks at lock, reservations are RPC-only and one shell modal claims celebrations — prevents replay/client-forged rewards.
- Web Push uses notifications.push_status + unique push_deliveries; push.server.ts sends on push_wake to /api/public/push/dispatch; public/push-sw.js never caches pages — isolates Push from Zalo.
- Content/Design notifications originate in content_notify/order_notify triggers with unique-name recipients and event+item+history+recipient dedup_key; switches live in content_notify_settings — every writer triggers the same notification.
- KPI periods use src/lib/kpi/timeframe.ts (Vietnam time); goals.metadata holds periodType/deadline; overlap filtering doesn't clone monthly goals — preserves historic KPI data.
- Order quotes: separate oq_flows and snapshot oq_rounds; published responses immutable; writes via SECURITY DEFINER oq_* RPC; private order-quotes images. Change private.oq_missing with src/lib/orderQuotes/logic.ts; oq_publish_response auto-completes under FOR UPDATE; delete images via oq_storage_cleanup — preserves history and access control.
- Order tracking (ot_*) is independent of oq_* and Task: client SELECT-only, writes via ot_* SECURITY DEFINER RPCs with dependency/qty checks under FOR UPDATE; src/lib/orderTracking/logic.ts mirrors those rules for UI hints — backend stays authoritative.
- Progress forms submit capability; detail reads legacy in_progress/existing_code — preserves history.
- Order-quote durations are computed only in private.oq_round_metrics (exposed via oq_job_times/oq_report_rows, report perms oq.report_own/all/export checked server-side); src/lib/orderQuotes/report.ts only filters/aggregates — one formula for list, detail, report, Excel.
- Order tracking reschedules: ot_reschedules (one pending per order), only the opposite side (sale↔supply) replies via ot_reschedule_* RPC; accepting changes due_date while original_due stays — two-party agreement enforced server-side.
- ot_* notifications are in-app only (zalo_status ineligible, push_status none, notifications.ot_order_id) — no Zalo/Push until explicitly requested.
- Signal role scope: app_roles.signal_scope_all/signal_scope, enforced by private.sig_scope_ok in opportunity_signals RLS + sig_scope_guard trigger (covers every RPC); sale/creator branches unscoped — list, counters, report, export all read through the same RLS.
- Casso webhook verifies HMAC/timestamp, active bank_accounts and (provider, provider_transaction_id) dedupe; clients SELECT-only. fin_confirmation_guard runs SECURITY DEFINER with fixed search_path and unchanged auth.uid() checks — service-role INSERT planning must resolve private helpers without broad schema grants.
- Tiền Về: writes only via fin_* SECURITY DEFINER RPCs with row locks; private.fin_can_see governs transaction/event RLS and RPC visibility; fin_incoming_stats stays SECURITY INVOKER checking totals via auth.uid(); query caches are user-keyed. Authoritative confirmation_status/confirmed_by/confirmed_at; legacy status fields kept for audit. fin_claim confirms unowned rows atomically; fin_reconcile only confirms unowned other money without assigning Sale; keep reconcile permission IDs, never send accounting-approval notifications. Manual entries live in bank_transactions (source≠bank/provider=manual) via fin_manual_* RPCs, start unclaimed, one initial GMF via finManualNotify, soft-cancel — preserves bank data and financial privacy.
- Lead integrations (Facebook fbl_*, Website Forms wf_*): tables service-role-only; *.functions.ts check fbl_can_manage/wf_can_manage; AES-GCM seals tokens/keys. Webhook/submit persists event first, then claim→process→complete RPC atomically inserts signal + completion under row lock and rechecks enabled Form. Enabled-at gates new intake; retry bounded with backoff; notifications + post-commit Zalo wake stay outside intake. Disabled Forms store metadata only, never personal data; unique external id (leadgen_id/submission_id) prevents duplicates. WF keys sign HMAC-SHA256(timestamp.body), ±5min window, 60 req/min via wf_rate_hit; docs/website-forms-api.md is the plugin contract.
- Facebook discovery merges user/business Pages; encrypted sessions keep tokens out of UI, verify identity/lead access before saving — discovery is not eligibility.
- Quản trị Kinh doanh (biz_*): departments/members/KR metrics/deadline config read by all authenticated, writes only via biz_* SECURITY DEFINER RPCs checking biz.* perms; KR metrics are config rows (never hardcoded), deactivated not deleted; membership history kept via effective_from/to so transfers preserve past periods; money numeric(20,0), counts non-negative int; in-module Settings page reuses RolePermissionMatrix over the shared Role store — no parallel permission system.
