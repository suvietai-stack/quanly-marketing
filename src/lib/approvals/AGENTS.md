# Approval Center (/approvals)

- Read-only aggregation layer: single RPC `approval_center_read` unions todo/mine/done from biz_approvals_read, fr_steps, leave_requests, leave_request_events, attendance_explanations, orders, ot_reschedules, profiles, videos, web_contents, social_posts, tasks, oq_flows, sao_redemptions, k3_kpi_results/acceptances — each branch mirrors its source decide RPC/UI eligibility exactly (permission key + designated reviewer/approver field when one is set, via cw_uid name resolution); no new approval tables, statuses, or duplicate workflow logic. Badge = todo length only; navigation/mobile button gated by the RPC's eligible flag.
- Every branch is wrapped in its own EXCEPTION block feeding the result's `errors` array — one failing source must never break the whole center, and the UI shows a warning instead of a fake empty state. New sources: add a branch + a sourceGroup/GROUP_LABELS entry; unknown sources fall back to their raw key as label.
- Deep links use internal router navigation (parseApprovalUrl) and each module page keeps the record id in its URL (?open=, ?post=, ?open_opt= via src/lib/deep-link.ts) so refresh/back works; done items show "Xem chi tiết".
- Performance (0478): the biz branch reads private.approval_center_biz_read(), a pg_get_functiondef copy of biz_approvals_read() limited to pending runs or runs with the caller's own events — keep it in sync when biz_approvals_read() changes. "Done" history branches prefilter with `data->'history' @> [{byId}]` (GIN jsonb_path_ops); keep that shape so the index is used. Client sorts mine/done with `time()` (handles Postgres text timestamps) and renders lists progressively.
