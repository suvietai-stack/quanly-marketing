# Base organization permissions
- Chart rows are shared (unit,title) groups with distinct effective holders; new chart appointments omit historical slot IDs and title history includes every former slot — prevents per-person positions without erasing history.
- RoleCatalog is the sole inline Role editor; reductions use the existing actor-bound preview/apply and server obligation guard, never a blanket client prohibition. Shared checklists use explicit server policy keys and dependency hints, preserving native scope gates.
- Common is one active-account source in the existing Role rules/provenance pipeline, never per-user Role links; its checkbox readiness is explicit and own-only, with K3 unavailable until application-scope enforcement is accepted.
- Canonical Role drafts use new audited ID/key pairs, never catalog_state alone; legacy Roles remain untouched and are excluded from new slot selectors. Only server-reviewed canonical creation may persist draft IDs, preventing mixed legacy rights or name-based mapping.
- Personal writes require actor-bound expiring preview, unchanged direct Roles and additive-only save; active replace stays blocked and per-user audit preserves old state without a fourth source.
- Pending shared-position cutover resolves every titled appointment through (unit,title) V2 binding; slot IDs stay historical and legacy title fallback is retired together with provenance reads — prevents divergent permission sources without rewriting appointments.
- New/reactivated Marketing task rows carry eligibility_enforced; historical rows remain compatible until confirmed cutover, preserving live rights and independent Design specialties.
- Positions are (unit,title)→one Role with many concurrent holders; org_position_roles is written only via org_change position_role (audited); new appointments reject historical slot IDs — avoids hard-coded headcount.
- role_source_rows feeds staff provenance and distinct catalog counts; native CRM/3K/workflow gates remain authoritative until their separate source-scope cutover is verified.
- Title Role links reference original app_roles; full-Role active remains fenced, explicit enabled_permissions may activate audited personal capabilities through live assignment intervals. Unverified management scope stays draft; direct user_roles and business appointment evaluators stay unchanged.
- Assignment specialty IDs and server-reviewed Role signatures live on canonical assignment data; only org_change may add them, and ending the assignment removes only marketing_appointment rules — manual specialty decisions stay unchanged.
- Canonical org_units/org_titles/org_assignments retain typed source facts and stable IDs; org_change uses actor-bound expiring preview/apply, rollback preview and atomic projection/audit. Base JSON is compatibility state, not an independent organizational writer.
- Only audited supported keys may activate; unsupported rules remain drafts. Preserve specialized business/CRM and legacy role evaluators without restoring retired business-role grants.
- Permission reads are user-matched and invalidated at server transitions; native scope/workflow restrictions remain authoritative and own CRM grants pass the shared ownership boundary.
- Titles may carry unit_id as per-department chart slots (manager titles single-holder, staff multi); seeds are idempotent name-matched merges, titles alone never grant permissions, and staff chart reads use base_org_chart_read without permission data.
- org_workspace_read is user-scoped; org_change is the only admitted organization writer, with selected-ID end/cancel deltas, DENY precedence and manager self-promotion guards. Old Base/Biz public mutation EXECUTE and projection DML are revoked; private historical integrity/sync helpers remain. - Marketing specialties auto-grant only permissions in private.mkt_specialty_permission_ready (personal, verified) via private.mkt_specialty_rules chained into base_rules; DENY still wins, specialty edits stay Super-Admin-only until a cycle-safe unit-scope resolver exists.

- Marketing task rights = configured app_roles.permissions ∩ backend-ready keys ∩ active source ∩ Marketing eligibility (legacy rows included); never module whitelists inside resolvers — Role stays the single customizable source, trimming happens via audited role_catalog_change.
- Default suggestions use responsibilities, never legacy unions; retain desired existing rights and policy-gate additions. Risk labels are editor-only; pending reduction guard rechecks unresolved approver responsibility at preview and apply.
- V2 specialty Roles are read directly, so Role edits must not rewrite canonical appointment signatures; audit-based restore accepts only exact before/after rows, and Design specialty rebinding requires equal effective keys.

- Company K3 migration stages add nullable frozen org attribution and private scope helpers before replacing public gates/writers; company obligations stay disabled until explicit prospective cutover — preserves legacy data and prevents retroactive discipline.
