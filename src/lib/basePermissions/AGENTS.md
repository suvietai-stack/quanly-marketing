# Base organization permissions
- Title Role links reference original app_roles but remain database-fenced drafts until per-module scope enforcement is verified; direct user_roles and business appointment evaluators stay unchanged.
- Store organization/default/direct/bundle configuration as revisioned JSON; writes require Super Admin, actor-bound expiring previews and atomic audited apply to prevent silent changes.
- Only audited supported keys may activate; unsupported rules remain drafts. Preserve specialized business/CRM and legacy role evaluators without restoring retired business-role grants.
- Permission reads are user-matched and invalidated at server transitions; native scope/workflow restrictions remain authoritative and own CRM grants pass the shared ownership boundary.
- Titles may carry unit_id as per-department chart slots (manager titles single-holder, staff multi); default-structure seeds are idempotent name-matched merges, titles never grant permissions, and staff chart reads use base_org_chart_read without permission data.
- org.* keys carry optional rule unit_id as management scope (unit + descendants, DENY wins); membership-only changes apply through base_org_membership_apply (revision-locked, scope-checked per affected unit, manager slots need org.appoint_manager, no self-appointment to manager slots), while structure/permission changes keep the Super Admin preview/apply path with the ÁP DỤNG PHÂN QUYỀN confirmation. org.manage_structure/org.manage_permissions stay draft until backend support exists; base_org_read redacts grants/bundles/defaults for non-Super-Admin readers.
