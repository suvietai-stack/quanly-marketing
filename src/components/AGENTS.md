# Navigation architecture
- Personal permission selection uses supplemental baseline only; one actor-keyed authenticated catalog SELECT merges by key with local labels/subgroups, lazy rendering and existing actor/target effective data remain informational — keeps Role editing and server grant guards unchanged.
- Organization personnel actions use in-dialog org_change preview/apply with selected-ID deltas; title and child-unit editing lives in the unit drawer, while Role tools stay separate. Immediate deltas use the server clock and Marketing task edits end/recreate only the selected assignment — preserves audited intervals and independent sources.
- Mobile Launcher and desktop Sidebar consume the same visibleNavigation output. Root search selects area/dashboard; user-keyed local pins store only route preferences and are revalidated against live visibility. Launcher pin editing uses a user-scoped draft in the home customization dialog and commits to the existing storage key only on Save; tiles remain navigation-only — preserves permissions, preferences and business data without a second catalog.
- Authenticated AppShell owns one persistent MobileAppChrome for all routes; document scrolling uses measured safe-area chrome offsets, and back navigation accepts only history entries observed by this mounted user shell — avoids external/login back targets and duplicate module layouts.
- Mobile 3K and Leave reuse existing queries, mutations and evaluation helpers; opt-in dialog/sheet classes apply below the shell breakpoint, and direct Leave tiles pass only an initial form type — keeps desktop and authoritative business behavior intact.
