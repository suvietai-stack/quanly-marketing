# Business management (biz) rules
- Business: scoped biz_* RPCs, serialized organization/transfers, immutable content/workflow snapshots, final-official fences and audited Super Admin intervention; plans never enter approvals. Catalog appointments coexist with legacy managers under shared interval guards and Role scope ceilings; titles never grant actions. Monthly source/one version, exact strings/NULL, frozen first deadline, VN time and user-keyed caches preserve history. No demo mode: dashboards read operational data only and show empty states.
- Biz Dashboard hierarchy (Toàn Khối→Hệ→Phòng→Nhóm→NV) aggregates server-scoped enriched facts client-side in src/lib/biz/hierarchy.ts mirroring biz_dashboard_aggregate; KRs merge only by Admin-set biz_kr_metrics.standard_code plus identical unit/kind/aggregation/direction, never by name — keeps scope server-side and prevents false merges.
- Reports: first submission is official instantly (biz_document_save sets approved + official_version_id, no approval run, no notification); only later adjustments (biz_document_start with mandatory reason) enter workflows, carry previous_items in the snapshot, and never replace official figures until decided. Attachments are optional https link JSONB (max 10, regex is portable — no bounded repetition); plans still require a Google Docs link on submit.
- Plans page (BizPlans.tsx) splits "Kế hoạch của tôi" / "Kế hoạch trong phạm vi quản lý" auto-shown by scope; view tracking lives in biz_document_views (per version × viewer) via biz_document_open RPC — never a shared is_viewed flag, never recorded on list/dialog views, only on explicit document open. my_view (none/unopened/opened/new_version) comes from biz_documents_read; biz_plans_unviewed feeds the Dashboard "Kế hoạch chưa mở của tôi" card.
- Plans and Reports share the "Công việc của tôi" section (BizMyWork.tsx) fed by read-only RPC biz_my_work(kind): it auto-lists open/overdue/next periods plus stale changes/pending late requests, never creates drafts, and skips periods where the user has no department (biz_period_department NULL) and no document — personal obligations must not depend on the management filter. Action buttons follow biz_deadline_phase (open→submit, overdue→late request flow, closed→read-only).
- Deadline config is 3 milestones per kind (open/due/late_close, month offset -1..12, per-period exceptions) in biz_deadline_config; biz_deadline_at stays the due milestone for frozen history. First submissions are gated server-side by biz_deadline_phase (not_open/closed block, overdue needs an approved one-shot biz_late_requests row marked used atomically, Super Admin bypass is audited); resubmits after revision requests are never gated. Auto phase notifications ride the 5-minute wf/recover-cron pulse via biz_deadline_auto_notify (service_role only, dedup_key idempotent); config changes append to biz_deadline_config_log.
- Cài đặt không còn tab Phòng ban: Phòng/Nhóm/nhân sự/Trưởng Phòng quản lý duy nhất tại Cơ cấu tổ chức (biz_org_save/biz_appointment_save). Nguồn chính thức của Trưởng Phòng là biz_management_assignments/biz_appointments qua biz_scope_ok/biz_resolve_position; biz_department_members.is_manager chỉ là fallback legacy cho phòng chưa ánh xạ Hệ và biz_member_save từ chối ghi is_manager=true — tránh hai nơi hiển thị quản lý khác nhau.
